# מערכת ניהול תורים (Appointments System)
פרויקט אמצע קורס – פייתון

## תיאור כללי
מערכת שורת-פקודה (CLI) לניהול תורים עבור עסק מסוג מספרה/קליניקה/סטודיו,
הכתובה בפייתון ושומרת את כל הנתונים בבסיס נתונים SQLite מתמשך (persistent).
המערכת כוללת ניהול תורים מלא, וכן שני בונוסים: ניהול לקוחות וחשבוניות מס,
וניהול לידים.

## איך מריצים את הפרויקט
1. יש לוודא שמותקן פייתון 3 (נבדק על פייתון 3.12, אך יעבוד על כל 3.8 ומעלה
   מכיוון שנעשה שימוש רק בספריית התקן - sqlite3, datetime, os).
2. אין צורך בהתקנת חבילות חיצוניות (pip install) - כל הספריות הן חלק
   מספריית התקן הפנימית של פייתון.
3. יש לחלץ את קובץ ה-ZIP ולהיכנס לתיקיית הפרויקט בטרמינל:
   ```
   cd appointments_system
   ```
4. מריצים את הקובץ הראשי:
   ```
   python main.py
   ```
   (במחשבים מסוימים ייתכן שיש להשתמש בפקודה `python3` במקום `python`).
5. בהרצה הראשונה ייווצר אוטומטית קובץ `appointments.db` בתיקיית הפרויקט -
   זהו בסיס הנתונים, והוא **אינו** כלול בקובץ ה-ZIP (כפי שנדרש בהנחיות ההגשה),
   אלא נוצר אוטומטית ע"י הפונקציה `init_db()` בכל הרצה מחדש אם הוא לא קיים.
6. הפרויקט פועל דרך תפריטים בטקסט: מזינים מספר ולוחצים Enter כדי לבחור
   פעולה, וחוזרים לתפריט הקודם עם האפשרות `0`.

## מבנה הקבצים ותפקיד כל קובץ
| קובץ | תפקיד |
|---|---|
| `main.py` | קובץ ההרצה הראשי - כל התפריטים והאינטראקציה עם המשתמש (input/print) בלבד. |
| `database.py` | ניהול החיבור לבסיס הנתונים SQLite ואתחול הטבלאות מתוך `schema.sql`. |
| `schema.sql` | הגדרת סכמת בסיס הנתונים - כל הטבלאות, המפתחות הראשיים והמפתחות הזרים. |
| `appointments.py` | לוגיקת ניהול התורים - הוספה, הצגה, עדכון סטטוס, מחיקה, בדיקת התנגשויות. |
| `customers.py` | לוגיקת ניהול לקוחות וחשבוניות מס (בונוס 1). |
| `leads.py` | לוגיקת ניהול לידים והמרתם ללקוחות (בונוס 2). |
| `utils.py` | פונקציות עזר משותפות: ולידציה של תאריך/שעה, קלט בטוח, הדפסת טבלאות. |

כל קובץ אחראי על תחום אחד בלבד (הפרדת אחריות - Separation of Concerns), וכל
פונקציה במודולי הלוגיקה כוללת docstring ותגובות בעברית שמסבירות מה היא עושה
ובאיזו דרישה מהמסמך היא מטפלת.

## מה מומש - מיפוי מלא לדרישות המסמך

### דרישות טכניות (חובה)
- **פייתון + SQLite**: כל הנתונים נשמרים בבסיס נתונים SQLite אמיתי
  (`appointments.db`), ללא קבצי טקסט/CSV וללא שמירה בזיכרון בלבד - ראו `database.py`.
- **סכמת בסיס נתונים בקובץ נפרד**: `schema.sql` מכיל את כל הגדרות הטבלאות.
- **קוד מודולרי**: הפרויקט מחולק ל-7 קבצים לפי אחריות (ראו טבלה למעלה).
- **טיפול בשגיאות ותקינות קלט**: לדוגמה, לא ניתן להוסיף תור עם שדה ריק
  (`appointments.add_appointment`), תאריך/שעה בפורמט שגוי נדחים כבר בממשק
  (`utils.input_date`, `utils.input_time`), וסטטוסים לא חוקיים נדחים
  (`appointments.update_status`, `leads.update_lead_status`).
- **קובץ README**: קובץ זה.

### דרישות פונקציונליות - ליבת הפרויקט (חובה)
- **הוספת תור חדש** (שם לקוח, סוג שירות, תאריך, שעה) - `appointments.add_appointment`.
- **הצגת רשימת כל התורים** - `appointments.get_all_appointments`.
- **עדכון סטטוס תור** (ממתין / בוצע / בוטל) - `appointments.update_status`.
- **מחיקת תור קיים** - `appointments.delete_appointment`.
- **מניעת התנגשויות בסיסית** (בונוס שצוין כ"יתרון") - `appointments.check_conflict`,
  שנקראת אוטומטית לפני הוספת תור חדש ומתריעה למשתמש אם כבר קיים תור
  פעיל באותו תאריך ושעה, עם אפשרות לאשר בכל זאת או לבטל.

### בונוס 1: ניהול לקוחות וחשבוניות מס
- טבלת `customers` נפרדת (שם, טלפון, אימייל, כתובת).
- הוספה, צפייה ומחיקה של לקוחות - `customers.add_customer`,
  `customers.get_all_customers`, `customers.delete_customer`.
- קישור בין תור ללקוח קיים - השדה `customer_id` בטבלת `appointments`
  הוא מפתח זר לטבלת `customers` (אופציונלי, כדי לא לפגוע בגמישות הליבה).
- יצירת חשבונית מס עם מספר ייחודי (בפורמט `INV-0001`, `INV-0002`...),
  סכום ותאריך - `customers.create_invoice`.
- צפייה בהיסטוריית תורים וחשבוניות לכל לקוח - `customers.get_customer_history`.

### בונוס 2: ניהול לידים (Leads)
- טבלת `leads` נפרדת (שם, טלפון, מקור פנייה, סטטוס, הערות).
- הוספת ליד ועדכון סטטוס (חדש / בטיפול / הפך ללקוח / נדחה) -
  `leads.add_lead`, `leads.update_lead_status`.
- המרת ליד ללקוח קיים במערכת - `leads.convert_lead_to_customer`, שיוצרת
  רשומת לקוח חדשה מנתוני הליד ומעדכנת את סטטוס הליד אוטומטית.

## החלטות עיצוב שכדאי לציין למרצה
- **פורמט תאריך ושעה**: נבחר פורמט `DD/MM/YYYY` (למשל `25/12/2026`) ו-`HH:MM`
  (למשל `14:30`) כדי שיהיה נוח וטבעי למשתמש ישראלי; הוולידציה מבוצעת
  באמצעות `datetime.strptime` במודול `utils.py`, כך שלא ניתן להזין תאריך
  לא קיים (כמו 31/02/2026) או שעה לא חוקית.
- **מפתחות זרים (Foreign Keys)**: מכיוון של-SQLite אכיפת Foreign Keys כבויה
  כברירת מחדל, הוספתי `PRAGMA foreign_keys = ON` בכל פתיחת חיבור
  (ב-`database.get_connection`) - בלי זה, ה-`ON DELETE CASCADE` וה-`ON DELETE
  SET NULL` שהוגדרו בסכמה לא היו נאכפים בפועל.
- **מחיקת לקוח**: נבחר `ON DELETE SET NULL` על תורים (התור נשאר בהיסטוריה
  גם אם הלקוח נמחק, רק "מתנתק" ממנו) לעומת `ON DELETE CASCADE` על חשבוניות
  (חשבוניות ללא לקוח משויך אין להן משמעות עסקית, ולכן הן נמחקות יחד עם הלקוח).
- **מספרי חשבונית**: נוצרים אוטומטית ובאופן רציף (`INV-0001`, `INV-0002`...)
  כדי להבטיח ייחודיות בלי להסתמך על קלט ידני מהמשתמש.

## הערה להגשה
בהתאם להנחיות המסמך, קובץ בסיס הנתונים `appointments.db` **אינו** מצורף
ל-ZIP המוגש - הוא נוצר אוטומטית בהרצה הראשונה של `main.py`.
